# 安全与隐私

## 本地处理范围

这是一个本机桌面工具。资源列表和探测任务由 Electron 主进程处理；目录缓存写入 Electron userData 路径。项目不需要用户登录，也不应要求用户提供 FOFA 密钥或 GitHub Token。

## 网络行为

当前软件主要执行两类网络访问：

1. 获取公开 ProxyIP 目录：all.json，必要时回退 all.txt。
2. 对用户选定的候选 IP:Port 进行 TCP/TLS/HTTP 探针检测；每个节点可能同时触发 IPv4 探针和 IPv6 探针。

因此：
- 开始一轮检测会产生真实网络流量；
- 持续检测会周期性重复连接；
- 默认应限制检测范围、并发、超时，并提供明确的停止按钮；
- 不要在后台启动无限制全量扫描；
- 增加新探针或诊断行为前，必须说明会访问哪些主机、发送什么请求以及频率。

## Electron 安全边界

- BrowserWindow 应保持 contextIsolation: true。
- Renderer 应保持 nodeIntegration: false。
- 渲染层使用 preload 中明确列出的 API。
- 不把整个 ipcRenderer、require 或 Node.js 全局暴露给页面。
- 所有打开外部 URL 的入口都应校验协议和目标；不要允许任意文件/脚本打开。
- 远端返回的 IP/城市文本被视为不可信数据，在 DOM 中渲染时进行文本转义，不把它拼接成可执行 HTML。

## 安装脚本和第三方依赖

- 不为消除 npm 脚本警告而无差别批准所有包的安装脚本。
- 清晰区分 npm 包安装与 Electron 平台二进制下载。
- 安装器必须限制下载重试，避免无限死循环。
- 不要把 Token、密码、私有仓库凭据、完整用户目录日志或机器标识写到远端。
- node_modules、dist、日志、凭据文件和临时下载文件不应提交到 Git。

## 用户数据与诊断日志

安装日志用于定位 Node/npm/Electron 下载错误。发送给维护者之前，用户应检查其中是否包含个人路径、用户名或其他不希望分享的信息。代码不应收集或上传无关的系统信息。

## 风险提示

ProxyIP 为第三方公开资源。探测结果可能因路由、运营商策略、端口过滤、TLS/SNI、节点状态或网络拥塞而变化。软件不保证匿名性、安全性、可用性，也不应将节点“成功返回出口 IP”等同于可信或安全。不要对自己无权测试的主机实施超出本软件预期用途的高频探测。
