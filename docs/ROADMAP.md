# 路线图

路线图用于排序，不代表功能已实现。每次开工先查看当前 main，关闭已完成项，避免重复开发。

## P0 — 让 0.1.2 在 Windows 实际跑通

- [ ] 将 0.1.2 源码同步进 GitHub main。
- [ ] Windows 实测依赖安装，确认 Electron 主程序实际下载完成。
- [ ] 实测 Electron 启动、资源下载、JSON/TXT 解析、缓存读取。
- [ ] 实测 1 个或少量节点的探测结果、停止动作及错误显示。
- [ ] 验证便携版 EXE，确认版本、工件名称与启动行为。
- [ ] 把用户实际日志和结果归纳进累计开发日志（移除个人路径/隐私后再记录）。

## P1 — 稳定性与可观察性

- [ ] 细分连接失败、超时、TLS 错误、HTTP 错误、JSON 无效等结果。
- [ ] 测试一条探针成功、另一条失败的结果计算，确保 UI 不把部分失败隐藏。
- [ ] 复核平均延迟的统计口径，清楚区分未连接成功、失败样本和均值。
- [ ] 持续检测停止后能可靠退出等待与进行中的任务，不产生重复循环。
- [ ] 增加资源刷新失败、缓存失效、上游 JSON 结构变化的测试。
- [ ] 长列表虚拟化或分页的性能评估；保持启动默认只测有限范围。
- [ ] 缓存时间和上游生成时间显示明确。

## P2 — 地区分类和用户体验

- [ ] 验证国家、大洲、城市树与上游结构化字段相符。
- [ ] 明确标记上游未标注城市的节点。
- [ ] 加入可配置的测速间隔、并发与超时边界说明。
- [ ] 为表格加入排序指标解释和结果过滤选项。
- [ ] CSV 增加错误原因列与数据源/测试时间字段（若用户确认需要）。
- [ ] 提供仅在用户主动选择时进行全量检测的安全确认。

## P3 — 交付工程

- [ ] 增加 package-lock.json，建立稳定的锁文件维护流程。
- [ ] 为每个正式版本生成版本化构建报告和 SHA-256 校验文件。
- [ ] 根据项目所有者决定添加许可证文件，再发布明确的开源许可。
- [ ] 可考虑 GitHub Actions 的自动测试/Windows 打包，但先评估工作流可维护性与 runner 成本。
- [ ] 记录真实 Windows 端到端测试，不让 CI 单元测试掩盖安装器或外网问题。

## 暂时不做

- 不先接入 FOFA API，不要求用户购买或配置 API Key。
- 不用 ICMP Ping 取代实际 TCP/TLS/HTTP 代理探针。
- 不承诺根据国家/城市标签可推断实际物理路由。
- 不在没有实际需求的情况下引入大型框架或复杂数据库。
