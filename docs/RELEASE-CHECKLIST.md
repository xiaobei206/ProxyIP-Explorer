# 正式版本发布清单

每次只发布正式递增版本；例如 0.1.2 → 0.1.3。不要单独发布 FIX。

## 版本一致性

- [ ] package.json version 已增长。
- [ ] UI 显示版本已同步。
- [ ] 版本说明.txt 已更新。
- [ ] 测试确认 package/UI 版本一致。
- [ ] README、累计开发日志、会话交接已更新。
- [ ] 所有 ZIP/EXE/报告/SHA 文件名均包含项目名和版本号。
- [ ] 如果仓库有 package-lock.json，同步锁文件元数据；如果无锁文件，则明确记录是否计划新增，不得假称已同步。

## 代码和测试

- [ ] 阅读最新 main 和当前实现，没有覆盖他人新提交。
- [ ] 新行为已有自动化测试或解释为何不能自动测试。
- [ ] npm.cmd test 通过。
- [ ] 检查异常路径、停止按钮、并发上限、超时和错误日志。
- [ ] 检查 Electron 安全配置与 preload 暴露 API。
- [ ] 检查 .gitignore，不提交 node_modules、dist、日志、凭据或用户专属文件。

## Windows 验证

- [ ] 安装依赖从零开始通过。
- [ ] Electron 二进制存在，并能输出正确版本。
- [ ] 应用能真正启动。
- [ ] 真实上游 JSON 可获取并正确解析；TXT 回退经验证。
- [ ] 运行小规模探测，结果和延迟单位合理。
- [ ] 运行/停止/连续检测循环正常。
- [ ] 便携版 EXE 已实际生成并运行。
- [ ] 记录 Windows 版本、Node/npm 版本及结果。

无法完成的项目需在交付中明确标注“待验证”，不可打勾或声称通过。

## 提交和工件

- [ ] 查看 git diff 和 git status。
- [ ] 使用能描述实际变化的提交信息。
- [ ] 推送后核对 GitHub 文件、commit SHA 和 Actions（如启用）。
- [ ] 记录工件 SHA-256（仅对实际生成文件计算）。
- [ ] 更新 SESSION_HANDOFF.md，列出下一步和未解决问题。
