ABOUT THE PROBE

检测原理与指标说明

资源与地理分类：读取 https://zip.cm.edu.kg/all.json 的 data[].meta，包括 country、country_cn、city、region 和 colo.iata；JSON 城市信息缺失时不会冒充为精确城市。TXT 只用于补充国家代码。

本机测速：每个 IP:端口分别使用 SNI ipv4.090227.xyz 和 ipv6.090227.xyz 建立 TCP/TLS 连接，并向对应探针发送 HTTP GET，检查返回 JSON 中是否存在出口 IP。这是上游 CheckProxyIP 的探针思路在本机的独立实现。

检测实际做什么：对每个候选 IP:端口分别建立 TCP 连接，再用 ipv4.090227.xyz 与 ipv6.090227.xyz 作为 TLS SNI 握手并发送 HTTP GET。探针必须返回有效 JSON 且包含出口 IP，才算该路成功；至少一条成功则节点标记为“可用”。协议列会直接显示失败原因。

TCP 延迟：显示本机到候选 IP:端口实际建立 TCP 连接的耗时。即使后续 TLS/HTTP/出口探针失败，只要 TCP 已连上，仍会显示测得的延迟；只有两路 TCP 都连不上才显示“—”。延迟不是完整 HTTP 耗时，也不是 Cloudflare Worker 机房的延迟。

探针出口：成功时显示探针返回的出口 IP、国家/城市、ASN 和 CF 机房信息。这里的城市来自探针响应，不是静态 IP 库；若节点探针没有成功返回出口 JSON，就不会有这项城市信息。

注意：本机探测结果反映你当前电脑到候选节点的网络路径，不等于 Cloudflare Worker 机房到该节点的结果。某些网络会屏蔽 ICMP，但 TCP/TLS 仍可正常工作。
